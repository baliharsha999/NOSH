1. Senior Developer Orientation & Reading Roadmap

If you are auditing, evaluating, or extending this repository, this roadmap provides the exact 12-step path to understand how data moves from raw JSON objects to sub-10ms deterministic analytics, constraint-satisfaction matching, and grounded LLM narrative synthesis.

Core Engineering Principle: Zero-Hallucination Decoupling
Large Language Models are probabilistic next-token predictors; they cannot compute statistics, ensure constraint invariance, or remember large sets without hallucination. In NOSH, all calculations, rankings, allergen exclusions, and sister-recipe empirical citations are 100% deterministic algorithms. The LLM acts solely as a natural-language chef narrator receiving verified factual context.

4. Function-by-Function Algorithmic Reference Manual

Below is the complete algorithmic documentation for every critical function and class implemented in the codebase.

4.1 Module: backend/src/normalization.py

clean_raw_ingredient(raw_text: str) -> Optional[str] Time: O(K) | Space: O(K) where K = len(raw_text)

Purpose: Canonicalizes messy user strings or raw dataset ingredients into clean root noun phrases.

Algorithmic Steps:

  1. Lowercases string and strips Unicode punctuation and special characters via regex [^\w\s\-].
  2. Removes quantities, integer fractions, and decimal numbers (e.g. 2 1/2, 0.25).
  3. Tokenizes by whitespace and eliminates known measurement units from MEASUREMENT_UNITS (e.g. cup, tablespoon, ounce, gram).
  4. Eliminates preparation adjectives from PREPARATION_WORDS (e.g. chopped, minced, peeled, diced).
  5. Applies plural-to-singular lemmatization heuristic (e.g. tomatoes → tomato, onions → onion).
  6. Consults SYNONYM_MAP to canonicalize regional terms (e.g. scallion → green onion, groundnut → peanut).
  7. Returns canonical string, or None if string contains only stop words or units.
detect_allergens(ingredient_text: str) -> Set[str] Time: O(T · L) | Space: O(A) where A = num allergens

Purpose: Detects whether an ingredient triggers any of the 8 major allergen categories, with strict plant-dairy exception shields.

Algorithmic Steps:

  1. Evaluates PLANT_DAIRY_EXCEPTIONS: If ingredient matches peanut butter, almond milk, coconut cream, or soy milk, immediately bypasses the dairy allergen check to prevent false-positive allergen flags.
  2. Matches tokens against ALLERGEN_TAXONOMY dictionary using strict token-sequence word boundary check.
  3. Returns set of triggered allergen keys (e.g. {"peanuts"} or {"dairy", "gluten"}).

4.2 Module: backend/src/ingestion.py

build_inverted_index(data_path: Path, output_pkl: Path) -> RecipeIndexBundle Time: O(N · I) | Space: O(V + N) where N = 121,684, I = avg ings (8.2)

Purpose: Ingests the 121,684 curated recipes and constructs an in-memory inverted index of token-to-recipe sets.

Algorithmic Steps:

  1. Streams JSON objects from recipes_cleaned.json into memory.
  2. For each recipe, iterates through ingredient lines, extracts normalized tokens via extract_normalized_keys(), and detects allergen categories via detect_allergens().
  3. Appends recipe_id into the set posting list of each token in inverted_index[token].
  4. Appends recipe_id into the set posting list of each detected allergen in allergen_index[allergen].
  5. Stores structured metadata in lightweight Pandas DataFrame recipes_df containing columns: [id, title, source, num_steps, num_ingredients].
  6. Serializes bundle to recipe_index.pkl using Python's standard pickle protocol 5 for portability.

4.3 Module: backend/src/analytics_engine.py

compute_ingredient_cooccurrence(ingredients: List[str]) -> Dict[str, Any] Time: O(min(|P_1|, |P_2|)) ≈ O(1) in practice (~0.8ms) | Space: O(Intersection)

Purpose: Computes the mathematically exact intersection count and dataset percentage for multiple ingredients.

Mathematical Formulation:

S = ⋂_{i=1}^k Index[clean_raw_ingredient(t_i)]   |   P = (|S| / 121,684) × 100

Algorithmic Steps:

  1. Normalizes each query ingredient string to its canonical root token.
  2. Retrieves pre-computed posting set from self.inverted_index for each ingredient.
  3. Computes bitwise/set intersection: matching_ids = set.intersection(*posting_sets).
  4. Calculates exact percentage over total denominator N = 121,684 rounded to 2 decimal places.
  5. Returns reproducible formula, normalization methodology, and sample recipe titles.

Dataset Benchmark: For Garlic + Onion: |Garlic ⋂ Onion| = 16,244. Percentage: (16,244 / 121,684) * 100 = 13.35%.

rank_by_instruction_steps(target_ingredient: str, top_k: int, ascending: bool) Time: O(|Posting| · log(top_k)) using Min-Heap | Space: O(top_k)

Purpose: Identifies matching recipes for a target ingredient and ranks them by procedural instruction steps.

Step-Counting Heuristic Algorithm:

  1. Queries inverted_index for recipes containing clean_raw_ingredient(target_ingredient) (e.g. tomato matches 18,294 recipes).
  2. Filters recipes_df for matching IDs.
  3. Step count was pre-computed during ingestion: lines split on newlines ; if instructions are a single paragraph, split on sentence terminators . following sentence-boundary rules.
  4. Sorts filtered dataframe by column num_steps ascending.
  5. Returns Top-K recipes with their titles, step counts, ingredient counts, and stable IDs.

4.4 Module: backend/src/matcher.py

match(request: MatchRequest) -> MatchResponse Time: O(|Pool| · avg_ings) | Space: O(|Pool|)

Purpose: Implements Task 2 multi-constraint pantry matching with hard Boolean filters and explainable scoring.

Multi-Objective Scoring Formula:

Score = 0.6 · (|M| / |Pantry|) + 0.3 · (|M| / |Recipe|) - 0.1 · |U|

Algorithmic Steps:

  1. Input Expansion: Normalizes available items and hard exclusions. Expands exclusion taxonomy (e.g., peanuts expands to {"peanut", "peanut butter", "peanut oil", "groundnut", "groundnut oil"}).
  2. Hard Boolean Filter: Computes disqualified_ids = ⋃ AllergenIndex[excl]. Candidates pool is formed from recipes containing at least 1 pantry item. Eligible set: eligible = candidates - disqualified_ids.
  3. Step Bound Filter: If max_steps is provided, eliminates any recipe where num_steps > max_steps.
  4. Set Partitioning: For each eligible recipe, decomposes ingredients into:
    • Matched (M): Intersection of pantry tokens and recipe ingredients.
    • Missing (U): Recipe ingredients not present in the user's pantry.
  5. Scoring & Ranking: Evaluates multi-objective score rewarding pantry coverage while penalizing extra required shopping items. Sorts descending.
  6. Quantity Notice: Attaches notice stating that ingredient presence is validated at name-level, but quantity sufficiency was not verified.

4.5 Module: backend/src/substitution_engine.py

adapt_recipe(request: SubstitutionRequest) -> AdaptedRecipe Time: O(N) linear scan over titles | Space: O(Evidence)

Purpose: Implements Task 3 evidence-based recipe adaptation citing empirical local Recipe IDs, with an integrated External Web Search Fallback with Forced Structured Output (backend/src/web_search_engine.py) when local evidence is inadequate.

Algorithmic Steps:

  1. Base Recipe Resolution: Resolves recipe by stable ID or dish title search (e.g. Banana Bread with Pecans, ID: 78qGO.ejAdsFEJLRl08hVUjiji9zyG6).
  2. Functional Role Analysis: Queries CULINARY_ROLES to determine chemical role of target ingredient (e.g. egg as binder/leavener/moisture). Selects optimal culinary substitute (e.g. Mashed Ripe Banana (or Applesauce) at ratio 1/4 cup per egg).
  3. Sister-Recipe Empirical Miner: Searches local dataset for sibling dishes of the same genre (e.g. banana bread) omitting target ingredients. If found, cites exact local Recipe IDs (e.g. [ID: p174TykunvO./PLjDpl03RBTaXiOEdu] 'Vegan Banana Bread').
  4. Inadequate Local Evidence Web Search Fallback: If 0 local sister recipes are found (or for novel ingredients/uncommon dishes like gelatin in panna cotta), engages WebSearchEngine to query external culinary authorities (King Arthur Baking, Serious Eats, Food52), using Groq JSON mode (response_format={'type': 'json_object'}) for forced structured output citing verified external URLs and excerpts.
  5. Ingredient List & Procedure Rewriting: Formats substitutions and revises cooking instructions with technique notes.
  6. Sensory Trade-Offs & Safety Disclaimer: Computes culinary trade-offs for taste, texture, and preparation, and attaches the mandatory medical safety disclaimer.

4.6 Module: backend/src/guardrails.py

check_input_query(query: str) -> GuardrailCheckResult Time: O(P) regex evaluation | Space: O(1)

Purpose: Intercepts incoming queries before engine execution to evaluate prompt injections and missing metadata inquiries.

Algorithmic Steps:

  1. Matches query against INJECTION_PATTERNS (e.g. ignore instructions, system prompt, DAN mode). If matched, blocks query immediately with security policy message.
  2. Matches query against ABSENCE_PATTERNS (e.g. prep time, cook time, calories, macros). If matched, blocks query with the Absence-of-Data Integrity notice, citing schema boundaries and offering step ranking as an alternative.
  3. Returns passed=True and action ALLOW for valid culinary requests.

4.7 Module: backend/src/pipeline.py & backend/app.py

process_query(user_query: str, session_id: str, thread_id: str, use_llm: bool) -> Dict[str, Any] Time: Sub-15ms deterministic / ~1.5s with Groq LLM | Space: O(Turn)

Purpose: Production-grade langgraph.graph.StateGraph execution engine coordinating input guardrails, intent routing, domain specialist nodes, persistent SQLite session state, LangSmith tracing, and grounded LLM synthesis.

Observability: Decorated with @traceable(name="NOSH_Conversational_Pipeline", run_type="chain") to stream execution traces, prompt inputs, latencies, and thread metadata to LangSmith.

Algorithmic Steps:

  1. Passes query through NoshGuardrails.check_input_query(). If blocked, records turn in SQLite and returns immediately.
  2. Retrieves ConversationalSession by thread_id (or restored from SQLite database).
  3. Classifies intent: ANALYTICS, MATCHING, RESTRICTION_REFINEMENT, SUBSTITUTION, or SEARCH.
  4. If RESTRICTION_REFINEMENT, accumulates newly stated restriction (e.g. dairy) into session.accumulated_restrictions and re-executes active search with hard exclusions enforced.
  5. Routes to respective engine (Analytics, Matcher, Substitution, or LangChain Retriever).
  6. If use_llm=True, invokes LLMGenerator.synthesize() passing grounded deterministic data to Groq Qwen 27B. If offline or error, cleanly falls back to deterministic markdown formatting.
  7. Persists turn and memory state to SQLite database (nosh_sessions.db) via SQLiteSessionStore.save_turn().

4.8 Module: backend/src/session_store.py

SQLiteSessionStore(db_path: Path) Time: O(1) indexed lookup | Space: O(Turns) in SQLite DB

Purpose: Production SQLite persistence store for conversational threads, turn histories, and active constraints across application restarts.

Database Schema:

  • conversation_threads: thread_id (PK), created_at, updated_at, active_search_query, accumulated_restrictions (JSON).
  • conversation_turns: id (PK), thread_id (FK), turn_index, user_query, intent_detected, response_text, structured_data (JSON).

Key Methods:

  1. get_or_create_thread(thread_id): Restores existing thread state or initializes a new thread record.
  2. save_turn(...): Atomically inserts turn dialogue and updates thread timestamps & active constraints.
  3. load_turn_history(thread_id): Loads all past turns in chronological order for conversation resumption.
  4. list_threads(limit): Returns active threads with turn counts and last updated timestamps.

7. Core Architectural Decisions & Design Rationale

1. Why decouple analytics from the LLM?
Autoregressive transformers predict subsequent tokens based on probability distributions; they cannot calculate set intersections or count rows across 121,684 recipes. Routing analytical queries through our Inverted Index and Pandas engine produces 100% reproducible, verifiable numbers in under 1 millisecond, eliminating calculation hallucinations.
2. How is constraint invariance guaranteed against semantic drift?
Cosine similarity in dense embedding space frequently ranks "Peanut Butter Cookies" with high similarity to a user asking for "Cookies with NO peanuts" due to topical clustering. In NOSH, hard constraints are enforced as a strict Boolean filter prior to semantic ranking. Candidate recipes containing excluded allergens are completely removed before scoring. Hard constraints are never relaxed silently.
3. How are missing attributes handled without hallucination?
The schema contract of the Recipe Box dataset is explicitly monitored. Because preparation times, cooking times, and caloric breakdowns are not present in the dataset, the AbsenceOfDataGuardrail intercepts any query for these attributes and explicitly declares the data absence rather than permitting the LLM to invent plausible values.
4. How do you scale to 121,684 recipes on a local laptop?
The pre-computed inverted index bundle consumes less than 35MB of RAM and loads in 2.2 seconds. Set intersection operations are executed in C-accelerated Python primitives. The entire architecture runs locally without requiring dedicated GPU infrastructure.

In alignment with modern software engineering practices, AI coding tools were utilized strictly as developer productivity accelerators for typing boilerplate, syntax validation, and test parameterization. All high-level system architectures, inverted index implementations, deterministic analytics engines, Boolean constraint solvers, and safety guardrails were independently designed, authored, and verified.
